The thesis, in four lines

Stamp, don’t fade. Things arrive by landing, not by appearing. Overshoot and settle. Weight is expressed by going slightly too far. The shadow snaps in on landing — not before, not gradually. Press has weight: active states go below rest, never just dim.

If an animation can’t be described in those terms, it isn’t this system. Opacity-only fades are the one thing this brand explicitly does not do — a silkscreen either printed or it didn’t.

The three curves

--ease-stampcubic-bezier(.2, 1.4, .45, 1)

Overshoot punch. Entrances, stamps, chip pops, anything that lands. The 1.4 is the overshoot — the reason things feel struck rather than moved.

--ease-snapcubic-bezier(.3, 0, .2, 1)

Quick settle. Hover lifts, presses, toggles, the theme flip. No overshoot — used where a bounce would read as sloppy rather than physical.

--ease-outcubic-bezier(.16, 1, .3, 1)

Long decel. Big travel and slow reveals — sheets, panels, ken-push on photography. The only curve that suits durations above 400ms.

The five durations

--dur-tap120msHover lift, button press. The .lift primitive.
--dur-quick200msChips, toggles, small selection states.
--dur-settle350msInteraction settle — a state change you caused. Not the theme flip; that claim was corrected 18.08.26.
--dur-enter700msEntrances, counters, kinetic type, and the Day↔Night flip via html.theme-settling.
--stagger90msDelay between siblings. Multiply by index; cap the total at ~6 items or the last one arrives late.

Naming convention

Verb-first

stamp-in, chip-pop, plate-wipe. The name says what happens, not where it is used — so it survives being reused somewhere else.

Component-prefixed if bound

cal-echo-a, live-pulse, skeleton-sheen. A prefix means this keyframe is not general — don’t borrow it.

Suffix -a / -b for pairs

Two layers of one effect, deliberately desynced. Never three.

Suffix -lg for breakpoint

Same effect, larger travel above 640px. If a keyframe needs a third size, the effect is wrong.

What "to fold in" means

The app ships roughly ninety named keyframes built on the three curves above. The sets are canon — those are the vocabulary, and a new surface should compose from them. The individual keyframe percentages still live only in the app source and should be dumped into this system in one pass, at which point this half of the table becomes exact rather than descriptive. Nothing here needs a decision; it needs one export.

Rules

One theme duration. The flip is 700ms via html.theme-settling, which transitions every surface, border, shadow and fill together and then releases back to interaction timing. Never animate the theme per component.

Two layers, not three. Every misregister and echo effect is exactly two plates. Three reads as a printing fault rather than a printing style.

Infinite animation is rationed. live-pulse, skeleton-sheen, marquee-ticker, rdSpin and ken-push — that is the whole list. Anything else that loops forever is decoration and will be cut.

Reduced motion kills all of it. The blanket prefers-reduced-motion rule means every animated state must be legible at rest. Design the rest state first.
