Why these are in the system

Each one was independently reimplemented at least twice across the app, the site and the studios — with different sizes, durations and colours each time. They are in the token layer now so the next surface imports them. If you find yourself writing a pulsing dot or a shimmer, it exists.

The rule

.misreg needs isolation:isolate and no background on the wrapper. The echo layers sit at z-index:-1; if the wrapper (or any ancestor up to the nearest stacking context) paints a background, they render behind that paint and vanish silently — no error, no warning, just a hero that lost its print. This has bitten twice. The class ships with isolation:isolate built in, so the remaining failure mode is putting a background on the same element.

.vt-heroFeed card slice → event page heroThe poster slice grows into the full hero. Both ends must carry the hook and only one element per route may have it — two .vt-heros on one page kills the transition for the whole document.

These are a route contract, not component styling

They belong to the pair of pages, not to the component. Adding .vt-hero to a card component means every list rendering that component breaks the transition. Apply them at the route level, to the one instance being navigated from.

Reduced motion

Four of these animate: .live-dot, .skeleton, .marquee and the theme flip. The system ships a blanket @media (prefers-reduced-motion:reduce) that kills all transitions and animations, so each degrades to its rest state — a static red square, a flat --surface-2 block, a clipped static line of text. Check the marquee: if its content is information rather than decoration, it needs a non-scrolling fallback layout, not just a stopped animation.
