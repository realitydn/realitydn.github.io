Two engines, not eight animations

Press pass is the arrival engine: cells stamp in, in token order, on a stagger. Mode swap is the change engine: the grid holds still and each changing cell pulls out and pops back in with its new ink — the same stamp, run twice. Between them they cover everything the mark needs to do — appear, change, and leave — because leaving is a press pass run backwards and every other behaviour is a recolour.

Each adaptation below is the same engine with different parameters. That is the point: one implementation, a parameter set per surface, so the app, the site and the studios can share the code the way they already share day-colours.json.

Both engines were already legal — press pass is stamp-not-fade by construction, mode swap only ever touches colour assignment. Neither can break cell order, radius, rotation or the size floor, which is why they survived and the other six didn't.

ENGINE A

Press pass

appear · leave

Cells scale from zero to full on --ease-stamp, sequenced in token order — the three majors, then the field. Never opacity. The overshoot is the ink hitting the paper; the stagger is the plate order.

pressPass(mark, {
  order     "token" | "whole"      // whole = one plate, no stagger
  stagger   ms                     // 0 · 20 · 60 · 90
  cell      ms                     // per-cell duration, 160–260
  direction "in" | "out"           // out reverses, bottom-up, on --ease-snap
  chain     [element, …]           // continue the stagger into type
})

fixed, not parameters
  · order is token order — always, both directions
  · scale only; no opacity, no rotation, no radius
  · one ease per pass; cells are plates, not characters
  · reduced motion → frame one is the finished mark
ENGINE B

Mode swap

change · hold

The geometry never moves, and no colour ever crossfades: each cell pulls — scales to zero on --ease-snap — and the replacement pops back in on --ease-stamp. Engine A's vocabulary applied to a plate change: the old plate lifts, the new one lands. Every mode in the canon card is a target, and so is a void set — a dropout is a pull with nothing following it.

modeSwap(mark, {
  to        "full" | "majors" | "daycode" | "ink" | assignment[]
  day       "mon".."sun"           // daycode only, from day-colours.json
  swap      "pullpop" | "cut"      // pullpop is the default; cut only at the size floor
  out / in  ms                     // pull 140 snap · pop 220 stamp
  stagger   ms                     // 0 · 40 · 90
  hold      ms | "manual"          // loop dwell, or wait for a trigger
  sequence  [mode, …]              // loops only
})

fixed, not parameters
  · assignments come from the mode table or day-colours.json
  · pull always precedes pop — the cell is empty between plates
  · unchanged cells never move; only the plates that change animate
  · voids ≤ 3, never adjacent, never the stock cell
  · no colour interpolation, ever — no crossfade, no tween
  · never bound to state, progress, validity or selection

Rules that come with the two engines

One arrival per surface

A surface gets one press pass. If the mark appears twice on a page, the second instance is static — the pass belongs to the first contact.

Chain outward, never inward

A chained pass may hand the stagger to type, never the reverse. The mark prints first; it is the plate the rest registers to.

Swap holds ≥ 1.2s

Below that, cuts read as flicker rather than plate changes. Manual triggers (day tick, theme flip, scroll) have no floor.

Never a swap on a near surface

App lists, menus, tickets, body copy: static mark. Recolouring beside text a person is reading looks like the UI is telling them something.

Never both engines at once

Stamping and swapping in the same beat is unreadable. The composite runs them in sequence with a 400ms gap, and that is the only legal pairing.

Never interpolate ink

No cross-fade, no colour tween, no blend between two assignments. The cell is empty between plates — that gap is the whole mechanic. This is the rule the studios are most likely to break.
